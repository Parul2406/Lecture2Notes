Lecture2Notes: lectures to notes, quizzes and searchable transcripts

A Python web application for teachers and students. Teachers upload a recording or paste a YouTube link. The server transcribes it with Whisper and a local language model turns the transcript into study notes, key definitions and a quiz, each linked to the moment in the lecture it came from. Students watch, read, search, take the quiz and get their marks; teachers see results live. All AI runs on the computer itself: no cloud APIs.

Python 3.14FastAPISQLAlchemy + SQLite FFmpegWhisper (faster-whisper)Ollama (gemma4) yt-dlpRuns fully on-device

Overview

The app covers the whole path from a recording to study material: accounts with two roles, upload or link import, transcription, AI-written notes and quizzes, sharing, graded quizzes with live results, editing and export.

Teachers

  • Upload a file or import from YouTube / a direct link
  • Watch every stage live; stop and continue jobs
  • Edit details, thumbnail, transcript, notes and quiz
  • Share lecture and quiz links; see quiz marks live

Students

  • Watch lectures, even while they're still being transcribed
  • Read notes; click any line to jump to that moment
  • Search the transcript while it follows the video
  • Take quizzes and see marks and explanations straight away

System

  • FFmpeg + Whisper for timestamped transcripts
  • A local LLM (Ollama) for notes and quizzes
  • Background jobs that keep running whatever page is open
  • PDF, Markdown and SRT export

AI & models used

Two kinds of AI, both running on the local machine. No lecture audio or text is sent to any external service and there is no per-use cost.

Whisper via faster-whisper

Speech recognition with segment and word timestamps, automatic language detection and about 99 languages. Runs on CTranslate2 with int8 quantisation on CPU; the Silero VAD filter skips silences.

Local LLM via Ollama

Writes the notes and quiz. Default model gemma4 (8B). The output is constrained to a JSON schema, so it always has the right shape. Ollama cloud models are refused, so lectures never leave the computer.

How notes are made

The transcript is split into parts of about 1,500 words. Each part is sent as numbered segments; the model returns sections, definitions and questions that point back at segment numbers, which become timestamps. A final call writes the summary.

Notes model comparison (RTX 3050 6 GB laptop, 5.7-minute lecture)

ModelTimeQuality
gemma4 default~70–90 sAccurate summaries; all quiz answer keys correct
llama3.1:8b~130 sWeaker: duplicated or wrong definitions

A one-hour lecture takes roughly 10–15 minutes for notes with gemma4. Any local Ollama model can be used via NOTES_MODEL.

Whisper model sizes (WHISPER_MODEL)

ModelParametersTrade-off
tiny / base~39 M / ~74 MFast, lower accuracy
small default~244 MA good balance for lectures on a CPU
medium~769 MBetter accuracy, slower on CPU
large-v3 / distil-large-v3~1.55 B / ~756 MBest accuracy; a GPU is recommended
  • Device: WHISPER_DEVICE=auto uses the NVIDIA GPU when the CUDA libraries are installed (pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12>=9,<10"; the app adds their folders to the DLL path itself), and falls back to CPU otherwise (checked with a warm-up encode). Precision is float16 on the GPU and int8 on the CPU.
  • Speed: on the RTX 3050 laptop GPU, a 5.7-minute lecture transcribes in about 25 s (~14x real time, under 1 GB of GPU memory).
  • Input: FFmpeg's 16 kHz mono WAV is read with NumPy and passed straight to the model, avoiding faster-whisper's own decoder.

Processing pipeline

1. DownloadLink imports only: yt-dlp fetches the video (H.264 preferred). Progress is live; a stopped download resumes.
→
2. ThumbnailA frame is grabbed 10% into the video (unless the teacher chose one).
→
3. FFmpegMono 16 kHz WAV. Skipped when continuing if it already exists.
→
4. WhisperTimestamped transcript, progress saved every 2 s.
→
5. NotesLocal LLM writes notes and quiz, part by part, with live progress.

Stopping and continuing

  • A Stop request is checked inside every long step: download progress, FFmpeg (polled and killed), every Whisper segment, every chunk streamed from Ollama. Queued jobs stop at once; running ones within seconds.
  • Finished work is kept. Continue works out the first unfinished stage from the files that exist and resumes there. A stopped transcription restarts at the beginning of that stage.
  • Stopping a notes regeneration keeps the previous notes.

Status lifecycle

downloading → uploaded → extracting_audio → transcribing → completed, or failed / cancelled (then Retry/Continue – <stage>)

Notes: pending → generating → completed, or failed / cancelled.

Sharing & quizzes

Share links

/s/<token> opens the lecture (video, notes, transcript) and /s/<token>/quiz the quiz, without an account. The token is random; New links replaces it and Stop sharing removes it.

Grading

The quiz page only contains questions and options. The server grades the submission, stores it, and shows the result page with the correct answers and explanations. Logged-in students are recorded under their account; others enter a name.

Live results

The teacher's Results tab polls every 4 s: submissions, average, each student's score, and the percentage that got each question right. If the quiz is edited or regenerated, older results are kept but marked as taken on a previous version.

Share links only reach students who can reach the server. By default it listens on 127.0.0.1 (this computer only). For students on the same network, run with --host 0.0.0.0 and open the app via the computer's network address (the Share dialog shows it), or set PUBLIC_BASE_URL.

services/worker.pyBackground jobs
  • Two single-thread pools: transcription (download, FFmpeg, Whisper) and notes (Ollama), so new uploads never wait behind notes.
  • stop_lecture / stop_notes: queued jobs are cancelled at once; running ones get a stop request they check frequently.
  • Skips finished stages when continuing; creates thumbnails; re-queues interrupted jobs on startup.
services/notes.pyNotes generation
  • Checks the model is downloaded and local (not an Ollama cloud model) before starting.
  • Splits the transcript into parts, streams each answer from Ollama (so Stop works mid-answer), validates it with Pydantic, retries once on bad output, clamps segment numbers and drops malformed questions.
services/quiz.py and routers/share.pyQuizzes and sharing
  • public_questions() strips answers before rendering; grade() checks submissions on the server and ignores tampered values.
  • version() fingerprints the questions so results from an older quiz are kept but not mixed with current ones.
  • /api/jobs feeds the tasks panel with running and recently finished jobs.
services/download.pyLink import
  • Only public http(s) URLs: the host is resolved and private, loopback and link-local addresses are refused.
  • Format preference H.264 → VP9 → anything but AV1; 720p cap; size and length limits; playlist links rejected; readable error messages.
services/export.pyExport
  • PDF: title block, summary box, contents, sections with timestamps, definitions table, quiz with answer key, transcript in paragraphs, running header and page numbers.
  • Unicode fonts with fallbacks (Nirmala UI, Microsoft YaHei, …) and harfbuzz shaping for Indic scripts.

Authentication & security

ConcernHow it's handled
Passwordsbcrypt with per-password salt; 8–72 bytes; changing it requires the current password and starts a fresh session.
SessionsSigned cookie holding only user_id; SameSite=Lax; optional HTTPS-only; cleared on login (no fixation).
Access controlTeacher-only actions return 403 for students; teachers can't open others' lectures (404); results and share settings are owner-only.
Quiz integrityAnswers never reach students' browsers; grading is server-side; out-of-range or non-numeric answers count as unanswered.
Share linksRandom 12-byte tokens; can be reset or removed at any time.
Link import (SSRF)Only http(s); hosts resolving to private, loopback or link-local addresses are refused, so the server can't be pointed at itself or the local network.
UploadsAllowed extensions only, random file names, streamed size limit; thumbnails are re-encoded with Pillow.
PrivacyWhisper and the notes model run locally; Ollama cloud models are refused.
XSS / commandsJinja2 auto-escaping; FFmpeg run with argument lists (no shell).
Not yet: CSRF tokens (SameSite=Lax gives partial protection), login rate limiting, email verification and password reset by email.

Testing & fixes

Each feature was tested end-to-end with FastAPI's TestClient on a copy of the database, using real Whisper and Ollama where noted, and checked visually with headless-browser screenshots in light, dark and phone layouts.

What was tested

  • Notes (real Ollama, gemma4): a 5.7-minute lecture in 3 parts produced 5 sections, 7 definitions and 9 questions in 72 s; all answer keys correct. Missing model, cloud model and Ollama-not-running are refused with clear messages.
  • Link import (real YouTube): download, title, Whisper transcript and notes in about 90 s; direct .mp4 links; local-network and invalid URLs refused; students can't import.
  • Sharing and quizzes: share pages work without login; no answers in student HTML; grading of correct, wrong, blank and tampered answers; logged-in attempts; live results; reset and disable.
  • Editing and settings: profile and password changes; details; thumbnails (frame, upload, auto, invalid image); transcript corrections; notes editor including validation; stages and Continue; watching while processing.
  • Stop (real Whisper): transcription stopped 0.17 s after the request; no Whisper process left behind, even when the server is force-killed; full runs and errors still work.
  • Re-download (real direct link): the old video stays during the download and is replaced only when the new copy is complete; stop and failure leave the video unchanged; old copies are cleaned up.
  • Seed: works on a fresh database (creates tables and accounts) and is safe to re-run.
  • Export: PDF, Markdown and SRT, including Hindi and Chinese text and non-English titles.

Limitations & roadmap

Current limitations

  • One transcription and one notes job at a time, inside the web process.
  • A stopped transcription restarts the Transcribing stage from the beginning.
  • Local disk storage; only nullable columns are migrated automatically.
  • No courses or enrollment: every student sees every lecture with a video.
  • No CSRF tokens, password reset by email or email verification.
  • Notes in languages other than English are weaker with an 8B model.

Possible next steps

  • Courses and enrollment, so students only see their own classes.
  • Password reset (email, or teacher resets a student's password).
  • Quiz options: time limits, one attempt only, export results to CSV.
  • Job queue (RQ/Arq) and Alembic migrations as the app grows.
  • Speaker labels (diarisation) and translation.
