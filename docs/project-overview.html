Lecture2Notes: lectures to timestamped transcripts

A Python web application where teachers upload recorded lectures (video or audio). The server extracts the audio with FFmpeg, transcribes it locally with OpenAI's Whisper speech-recognition model, and stores a timestamped JSON transcript in the database. Students can then read along, search, and jump to any moment of the lecture.

Python 3.14FastAPISQLAlchemy + SQLite FFmpegWhisper (faster-whisper)Runs fully offline

Overview

Version 1 covers the foundation of the product: user accounts with two roles, lecture upload, and an automatic speech-to-text pipeline that produces a structured, timestamped transcript.

Teachers

  • Sign up and log in as a teacher
  • Upload lecture videos or audio recordings
  • Watch processing progress live
  • Retry failed jobs, delete lectures

Students

  • Sign up and log in as a student
  • Browse all transcribed lectures
  • Play the lecture alongside its transcript
  • Click a timestamp to jump; search the text

System

  • FFmpeg extracts and normalises the audio
  • Whisper runs locally (no cloud API, no cost per minute)
  • Transcript stored as JSON segments: start, end, text, word timings
  • JSON API for status and transcripts

AI & models used

The only AI in v1 is speech recognition. It runs entirely on the local machine: no audio is sent to any external service and there is no per-minute cost.

Whisper (OpenAI, open-source)

A speech-recognition model trained on 680,000 hours of multilingual audio. It turns speech into text with segment- and word-level timestamps, detects the spoken language automatically, and supports about 99 languages.

faster-whisper (by SYSTRAN)

A reimplementation of Whisper on the CTranslate2 inference engine. It is up to 4× faster than the original implementation and uses less memory. It supports int8 quantisation on CPU and runs without PyTorch.

Silero VAD

A small voice-activity-detection model, run through ONNX Runtime and bundled with faster-whisper. With vad_filter=True, long silences are skipped before transcription, which speeds up processing and reduces "hallucinated" text during silence.

Model sizes (set with WHISPER_MODEL)

ModelParametersTrade-off
tiny~39 MFastest, lowest accuracy. Used in automated testing.
base~74 MFast, fair accuracy.
small default~244 MA good balance for lectures on a CPU.
medium~769 MBetter accuracy, noticeably slower on CPU.
large-v3 / distil-large-v3~1.55 B / ~756 MBest accuracy. A GPU is recommended.

How the model is run

  • Lazy loading: the model loads once, on the first transcription, and is reused afterwards. The weights download automatically from Hugging Face (Systran/faster-whisper-<size>) into data/models/.
  • Device selection: WHISPER_DEVICE=auto tries the NVIDIA GPU (CUDA) first. A one-second warm-up encode checks that the CUDA libraries really work, and if they don't, the app falls back to CPU automatically.
  • Precision: int8 by default, which is fast with low memory use on CPU. Use float16 on a GPU.
  • Decoding options: beam search with beam_size=5, VAD filter on, word timestamps on, and automatic language detection (or a fixed language through WHISPER_LANGUAGE).
  • Input: the 16 kHz mono WAV produced by FFmpeg is read directly into a NumPy float32 array and passed to the model, so the app does not depend on faster-whisper's own decoder (see fixes).
Not in v1 yet: an LLM for summarised notes, definitions or MCQs. The transcript JSON is designed to feed into that step later (see roadmap).

Processing pipeline

1. UploadTeacher submits a file. It is streamed to disk in 1 MB chunks, with the size limit checked as it goes.
→
2. QueueA lecture row is created with status uploaded, and the job goes to the worker.
→
3. FFmpegDrop the video, convert to mono, 16 kHz, 16-bit PCM WAV.
→
4. WhisperVAD filter, then transcription with segment and word timestamps. Progress is saved every 3 s.
→
5. StoreTranscript row saved: language, full text, segments JSON. Status becomes completed.

FFmpeg command

ffmpeg -hide_banner -nostdin -y -i <upload> -vn -ac 1 -ar 16000 -c:a pcm_s16le data/audio/lecture_<id>.wav

The flags mean: -vn drops the video, -ac 1 makes it mono, and -ar 16000 sets a 16 kHz sample rate, which is the rate Whisper works at. pcm_s16le writes uncompressed 16-bit samples. The command has a 1-hour timeout, and if it fails, the last lines of FFmpeg's error output are saved on the lecture.

Lecture status lifecycle

uploaded → extracting_audio → transcribing → completed  or  failed (Retry sets the status back to uploaded)

Students only see completed lectures. Teachers see all of their own lectures, whatever the status.

app/main.pyApplication entry point
  • Creates the FastAPI app with a lifespan handler. On startup it creates the tables (Base.metadata.create_all) and re-queues interrupted jobs (worker.resume_pending()). On shutdown it stops the worker.
  • Adds SessionMiddleware: cookie ltn_session, 14-day lifetime, SameSite=Lax, and an optional Secure flag.
  • Serves /static, registers the three routers, and redirects to /login?next=… whenever a login is required.
app/config.pySettings
  • A Settings class (pydantic-settings) that reads environment variables or .env. See Configuration.
  • session_secret: uses SECRET_KEY if it is set. Otherwise it generates a random key once and saves it to data/.secret_key, so logins survive restarts.
  • ensure_dirs() creates data/, data/uploads/ and data/audio/.
app/database.pyDatabase connection
  • SQLAlchemy engine and SessionLocal, with check_same_thread=False for SQLite so the worker thread can use the database.
  • SQLite pragmas: journal_mode=WAL lets web requests read while the worker writes, and foreign_keys=ON makes cascading deletes work.
  • get_db() is the FastAPI dependency that provides a database session to each request.
app/models.pyDatabase models
  • Enums: Role (teacher, student), MediaType (video, audio), and LectureStatus, which has an is_processing helper.
  • User has many Lectures. Each Lecture has one Transcript. Deletes cascade.
  • Transcript.as_dict() builds the JSON returned by the API. Details in Database.
app/security.pyAuthentication and authorisation
  • hash_password / verify_password: bcrypt with a random salt for each password.
  • login_user clears the session, then stores user_id. Clearing first prevents session fixation. logout_user clears the session.
  • Dependencies: get_current_user (may be none), require_user (redirects to login, or returns HTTP 401 for /api/*), and require_teacher (HTTP 403 for students).
  • safe_next_url only allows local paths in ?next=, which prevents open-redirect attacks.
app/templating.pyTemplates and helpers
  • Shared Jinja2Templates instance.
  • Flash messages stored in the session (flash / get_flashed_messages), for messages like "Uploaded", "Deleted" or errors.
  • timestamp filter: converts seconds to mm:ss or h:mm:ss.
app/routers/auth.pySign up, log in, log out
  • Sign-up checks: name required, valid email format, role is teacher or student, password 8 to 72 bytes, passwords match, email not already used. Errors re-display the form with the user's input kept.
  • Login gives the same "Invalid email or password" message for an unknown email or a wrong password, so it doesn't reveal which accounts exist.
  • All form posts end with an HTTP 303 redirect (the Post/Redirect/Get pattern).
app/routers/lectures.pyLecture pages and actions
  • get_viewable_lecture: teachers can only open their own lectures, and students can only open completed ones. Anything else returns 404.
  • get_owned_lecture: used for retry and delete, which only the owning teacher can do.
  • Upload: checks the file extension, saves under a random UUID name (the original name is kept in the database), rejects empty files, creates the lecture row, and queues the job.
  • Media: FileResponse with HTTP Range support, so the player can seek through long videos.
  • Delete is blocked while processing. Otherwise it removes the database rows and both files.
app/routers/api.pyJSON API
  • GET /api/lectures/{id}/status returns {id, status, progress, error}. The lecture page polls it.
  • GET /api/lectures/{id}/transcript returns the full transcript JSON. Uses the same access rules as the web pages.
app/services/media.pyFiles and FFmpeg
  • detect_media_type(): decides video or audio from the file extension.
  • save_upload(): writes the upload in 1 MB chunks and stops (deleting the partial file) once it exceeds MAX_UPLOAD_MB.
  • ffmpeg_binary(): uses FFMPEG_BINARY if set, then ffmpeg on the PATH, then the FFmpeg binary bundled with imageio-ffmpeg.
  • extract_audio(): runs the FFmpeg command and checks that the output is non-empty. Raises MediaError with a readable message on failure.
app/services/transcription.pyWhisper integration
  • get_model(): loads the model once, guarded by a lock so only one thread can load it, with the warm-up check and CPU fallback.
  • load_wav(): checks the WAV is 16 kHz, mono, 16-bit, then converts it to float32 values between −1 and 1.
  • transcribe(): iterates the segments as they are produced, calls on_progress(segment_end / duration), and returns {model, language, language_probability, duration, text, segments}.
app/services/worker.pyBackground pipeline
  • A ThreadPoolExecutor(max_workers=1): lectures are processed one at a time, because Whisper already uses every CPU core.
  • process_lecture(): set the status, run FFmpeg, set the status, run Whisper (saving progress at most every 3 s), store the transcript, mark it completed. On any error: roll back, mark it failed, save the error message.
  • resume_pending(): on startup, re-queues lectures still marked uploaded, extracting audio or transcribing.
  • Handles lectures deleted while queued, and logs unexpected errors so the worker thread never stops silently.
app/templates/ and app/static/User interface
  • base.html: top bar with the user's name and role badge, flash messages, page content area.
  • index.html (landing page), login.html, signup.html (role picker cards).
  • dashboard.html: teachers get the upload form (XHR with a progress bar) and their lectures with status. Students get the lecture list with teacher names.
  • lectures/detail.html: player, status polling, failure details with Retry, and the transcript with clickable timestamps, current-line highlighting and search.
  • style.css: CSS variables for light and dark themes, a responsive layout, and no external dependencies.

Authentication & security

ConcernHow v1 handles it
Password storagebcrypt with a random salt per password. Plain-text passwords are never stored. Passwords longer than 72 bytes are rejected, because bcrypt would otherwise silently ignore the rest.
SessionsSigned cookie (HMAC via itsdangerous). The cookie holds only user_id. It is SameSite=Lax, and can be made HTTPS-only with SECURE_COOKIES=true.
Session fixationThe session is cleared before every login.
Role checksEvery upload, retry and delete route requires the teacher role, enforced on the server (HTTP 403 for students).
Data isolationTeachers can't open other teachers' lectures, and students can't see unfinished lectures. Both get a 404, which doesn't reveal whether the lecture exists.
Account enumerationLogin gives the same error message for an unknown email and a wrong password.
Open redirect?next= only accepts local paths.
UploadsAllowed extensions only. Files are saved under random names, so users can't control paths. The size limit is enforced while streaming. Media files are only served to users with access.
FFmpegRun with an argument list (no shell), so file names can't inject commands. Has a 1-hour timeout.
XSSJinja2 escapes all user content automatically.
Secrets.env, data/ (database, uploads, secret key) and .venv/ are git-ignored.
Not yet: CSRF tokens (SameSite=Lax gives partial protection), rate limiting on login, email verification, and password reset.

Setup & running

git clone https://github.com/Parul2406/Lecture2Notes.git
cd Lecture2Notes
python -m venv .venv
.venv\Scripts\activate            # Windows   (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env            # optional
uvicorn app.main:app --reload

Open http://127.0.0.1:8000, sign up as a teacher, and upload a lecture.

  • No separate FFmpeg install needed: the app uses the binary bundled with imageio-ffmpeg when FFmpeg isn't on the PATH.
  • First transcription is slower: the Whisper model downloads once (about 480 MB for small).
  • NVIDIA GPU (optional): run pip install nvidia-cublas-cu12 nvidia-cudnn-cu12 and set WHISPER_COMPUTE_TYPE=float16. Without these libraries, the app falls back to CPU automatically.
  • Interactive API docs: /docs.

Testing & fixes

An automated end-to-end test ran the full flow through FastAPI's TestClient, using the tiny model. The test audio was a spoken clip generated with Windows text-to-speech, used both as a WAV file and wrapped into an MP4 video.

Result: all checks passed. Both lectures completed. The 12.9 s clip was transcribed word-for-word correctly: "Welcome to today's lecture on Python. We will discuss lists, dictionaries, and functions. A list is an ordered collection of items. A dictionary maps keys to values." Once the model was loaded, transcription took about 1 s on CPU.

What was tested

  • Logged-out users are redirected to login; invalid sign-up input is rejected; duplicate emails are rejected regardless of letter case.
  • A wrong password is rejected; an external ?next=//evil.com redirect is blocked.
  • Unsupported file types are rejected; video (MP4) and audio (WAV) uploads both go through the whole pipeline.
  • The status API, transcript API, lecture page rendering, and HTTP Range requests (206 Partial Content) for media.
  • Students can see completed lectures and transcripts, but can't upload or delete (403).
  • A teacher deletes a lecture; afterwards it returns 404.

Problems found and fixed

ProblemCauseFix
open() got an unexpected keyword argument 'metadata_errors' The newest PyAV (19.x) is incompatible with faster-whisper 1.2.1's built-in audio decoder. The app reads FFmpeg's 16 kHz WAV itself with Python's wave module and NumPy, then passes the samples straight to Whisper. PyAV is no longer used for decoding.
Library cublas64_12.dll is not found, then a hang The machine has an NVIDIA GPU, so device=auto chose CUDA, but the CUDA libraries weren't installed. A warm-up encode while loading the model checks that the device works. If it fails, the app logs a warning and reloads the model on CPU.
FFmpeg not installed on the system No ffmpeg on the PATH. Falls back to the FFmpeg 7.1 binary bundled with imageio-ffmpeg.

Limitations & roadmap

Current limitations

  • One background worker inside the web process, so one lecture is transcribed at a time.
  • Tables are created with create_all; there are no migrations yet.
  • Files are stored on the local disk.
  • No courses or enrollment: every student sees every completed lecture.
  • No CSRF tokens, password reset or email verification.

Possible next steps

  • Notes generation: send the transcript to an LLM to produce structured notes, key definitions, summaries and MCQs, with each item linked back to its timestamps.
  • Export to PDF or Markdown; teacher editing of transcripts.
  • Courses and enrollment, so students only see their own classes.
  • Job queue (Celery, RQ or Arq with Redis) and GPU workers to scale up.
  • Alembic migrations, PostgreSQL, and S3-compatible file storage.
  • Speaker labels (diarisation) and translation.
